# 录题约束总表

**这一份是约束的唯一清单。** 分散在各阶段文档里的规则，凡是「违反就会出错」的，都在这里。
新踩到的约束先补进本表，再在各阶段文档里讲「怎么做」。

每行三列：**约束** / **依据**（服务端强制 or 编辑口径 or 实测） / **违反后果**。
依据是 `服务端` 的，改不了，只能遵守；是 `口径` 的，要问编辑才能变；是 `实测` 的，是踩过的坑。

---

## A. 服务端硬约束（改不了，违反即报错）

| # | 约束 | 依据 | 违反后果 |
| --- | --- | --- | --- |
| A1 | `attachments[].placement` 只能是 `question`/`option`/`answer`/`explanation` | 服务端 | 写 `stem` 等会**静默 400**，图不显示也无明显报错 |
| A2 | 单个单元附件 ≤ 20 个 | 服务端 | 400 |
| A3 | `difficulty` 只能是 `容易`/`适中`/`困难` | 服务端 | 发布阻断 `legacy_difficulty`；筛选标签也按这三个 |
| A4 | `filterMetadata.categories` ⊆ `优选题`/`易错题` | 服务端 | 越界被拒 |
| A5 | `filterMetadata.difficultyValue` 取值 0–1 | 服务端 | 越界被拒 |
| A6 | `question_type` 只能取 27 个主类之一 | 服务端 | `invalid_type` 阻断 |
| A7 | `subtypes` 只能取 `references/filter-framework.json` 里列出的值 | 服务端 | 按子类筛选查不到该题 |
| A8 | **`group` 必须有 `material`，且有 `subquestions`** | 服务端 `publish_blockers` | `incomplete_group_unit` 阻断发布 |
| A9 | **组题每个子题必须有非空 `stem` 与 `answer`** | 服务端 | `incomplete_group_subquestions` 阻断发布 |
| A10 | **`unit_kind` 在 `POST /api/uploads` 时定死，`PATCH` 改不了** | 服务端 | 建错粒度只能**人工删除草稿后重传** |
| A11 | `standalone` 不应有 `subquestions` | 实测 | 前端按独立题渲染，子题不显示但占数据 |
| A12 | `PATCH` 的 `subquestions`/`attachments`/`filterMetadata`/`materialBlocks` 是**整体替换** | 服务端 | 只传一部分会把其余字段清空（2025 年两次清掉附件） |

| A17 | 确认/发布/撤稿/删除草稿只能人工 | 服务端 | harness 调用返 403（`human_confirmation_required` 等） |

## C. 题型与知识点映射约束

| # | 约束 | 依据 | 违反后果 |
| --- | --- | --- | --- |
| C1 | 题型与子类**不得新增/改名/合并** | 口径 | 筛选体系崩掉 |

| C4 | 阅读类设题角度写 `设题角度/阅读/*`，听力类写 `设题角度/听力/*` | 口径 | 标签越界 |
| C5 | 填空拼写类另加「答案考点」（该空考的词汇/语法叶子） | 口径 | 缺维度 |

| C8 | 真题里「单词拼写/完成句子/语音」等对照表**只允许词汇/语法/语音/答案考点**，不挂主题 | `check_tags.py` | 越界维度 |
| C9 | 各题型的允许维度以 `type-knowledge-map.json` 的 `by_type[题型].dims[].branch` 为准，超出即越界。易错清单：**完形填空只有「语篇体裁/主题」**（不挂设题角度、不挂词汇语法）；**选词/短文/教材语篇有「语篇体裁/主题/词汇/语法」**；**单词拼写只有「词汇/语法/语音」**；**完成句子只有「词汇/语法」**；**翻译有「词汇/语法/语用」**；只有阅读理解/任务型阅读才有 `设题角度/阅读/*` | `check_tags.py` | 越界维度 |
| C10 | 「主题」叶子的父级也占一行（如 `主题/人与社会/历史、社会与文化`），挂之前确认整段路径存在 | 目录 | `知识点路径不存在` |

## 两条只在文档里、脚本管不到的纪律

1. **粒度先确认再建批**。`unit_kind` 建完就改不了，删除要人工。接新册别（练习册、专项训练）
   第一件事是问清「一个单元 = 一道题，还是一道大题」，不要套用上一份资料的习惯。
2. **保留上传时的批次文件**。harness 读不到草稿，批次文件同时是
   「上传凭证」和「改草稿时唯一的现状来源」。
